Set up MipMap

Run one durable terminal conversation across projects, keep recent context detailed, and let the agent recover older source messages when it needs them.

Prerequisites

  • A recent Node.js release (Node 24 recommended), pnpm and Git.
  • Codex CLI or Claude Code installed and signed in. Automatic mode uses whichever authenticated agents are available.
  • An Anthropic API key with billing enabled for MipMap's separate summarization calls.
  • Optional: tmux for the split chat, status and activity layout.
Two separate jobs

Your installed Codex or Claude CLI handles agent turns. Anthropic's API handles conversation summaries. A provider subscription for agent turns does not pay for the Anthropic API summaries.

Step 1

Clone and install

git clone https://github.com/metatheoryinc/mem-mipmap.git
cd mem-mipmap
pnpm install

Commands in this guide run from the cloned mem-mipmap repository.

Step 2

Add the Anthropic summarization key

Create ~/.mipmap/.env and add your own Anthropic API key:

ANTHROPIC_API_KEY=your-key-here

Keep this file private. MipMap also reads an existing process environment and a repository .env; existing environment variables take precedence.

Separate paid API usage

Summarization makes Anthropic API calls and can incur charges. It does not use Claude subscription billing. Run the estimate command before importing a large history.

Step 3

Start your ongoing chat

Choose the repository where the agent should work:

pnpm mipmap chat -C /path/to/your/project

For chat, status and activity in one tmux session:

pnpm mipmap tmux -C /path/to/your/project

MipMap records the conversation in its local memory directory. Relaunching the same command returns to that memory rather than beginning with an empty thread.

Optional step

Enable hosted CLM routing

In the MipMap chat, enter:

/login

MipMap opens the hosted CLM device flow. Sign in with your Metatheory Google account and approve the code. The returned key is saved for MipMap only in ~/.mipmap/clm.json.

With routing enabled, CLM chooses the provider, model and effort for each turn from MipMap's currently permitted menu. The routing request includes the current task, brief context, permitted model options and available quota estimates. It never includes the complete memory view. The raw quota cache stays local.

Routing is not the lifecycle integration.

MipMap does not install CLM's Claude Code or Codex behavior hooks. Follow the separate Claude Code or Codex guide if you also want those checks.

Verify and inspect

pnpm mipmap status
pnpm mipmap usage
pnpm mipmap estimate
  • status shows the current agent, summarizer, memory and routing state.
  • usage summarizes recorded agent-turn and summarizer usage.
  • estimate estimates pending summarization work without making model calls. It is not a spending cap.

Use pnpm mipmap browse --open to inspect local conversation history, or pnpm mipmap activity to follow the activity log.

Update MipMap

git pull
pnpm install

Run the commands in your mem-mipmap clone, then restart the chat or tmux session. Your memory directory is separate from the application clone.

What leaves your machine

The append-only message log, summary tree, usage records and local Git history live in your MipMap memory directory. Treat that directory as private conversation data. Secret redaction runs before message text is stored, but it cannot guarantee that every sensitive value is removed.

Memory is local, but selected conversation content leaves the machine: agent context goes to the chosen Codex or Claude provider, and source material for summaries goes to Anthropic. If hosted CLM routing is enabled, the picker receives the current task, brief context, permitted model options and available quota estimates. It does not receive the complete MipMap memory or the raw local quota cache.

Billing

Agent turns use the authentication and billing of the selected installed CLI. Summaries make separately billed Anthropic API calls. Hosted CLM authentication is separate from both, and choosing a model does not reserve provider quota or guarantee availability.

Get help

Run pnpm mipmap status first. The project README covers terminal controls, imports, configuration variables and local memory inspection. No model call is needed to inspect status or run an estimate.
